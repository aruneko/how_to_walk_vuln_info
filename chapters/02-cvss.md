# 2. CVSS — 脆弱性の深刻度を表すスコア

> 目安時間: 10分

## この章のねらい

- CVSS のスコアと重大度の関係を理解し、ベクトル文字列を読めるようになる
- 現在主流の v3.1 と、普及が進む v4.0 の違いを説明できるようになる
- CVSS のスコアを使うときの注意点を理解する

---

第1章で何度か登場した **CVSS（Common Vulnerability Scoring System）** は、脆弱性の**深刻度**を 0.0〜10.0 の数値で表す共通の評価手法です。インシデント対応チームの国際団体 **FIRST** が仕様を管理しています。

## 2.1 スコアの読み方

スコアは、次の段階評価（重大度）とセットで使われます。この区切りは v3.1 と v4.0 で共通です。

| スコア | 重大度 |
|---|---|
| 0.0 | None（なし） |
| 0.1〜3.9 | Low（注意） |
| 4.0〜6.9 | Medium（警告） |
| 7.0〜8.9 | High（重要） |
| 9.0〜10.0 | Critical（緊急） |

CVSS の本体は数値ではなく、評価項目とその値を並べた**ベクトル文字列**です。スコアはこの文字列から計算されます。

```
CVSS:3.1/AV:N/AC:L/PR:N/UI:N/S:C/C:H/I:H/A:H   → 10.0（Critical）
│        │    │    │    │    │   └──────────── 機密性・完全性・可用性への影響
│        │    │    │    │    └──────────────── スコープ
│        │    │    │    └───────────────────── ユーザーの操作が必要か
│        │    │    └────────────────────────── 必要な権限
│        │    └─────────────────────────────── 攻撃の難しさ
│        └──────────────────────────────────── 攻撃経路（N = ネットワーク経由）
└───────────────────────────────────────────── バージョン
```

> **ポイント**：スコアの数字だけでなく、**ベクトル文字列を読む**習慣をつけましょう。「ネットワーク越しに、認証なしで、ユーザーの操作なしに攻撃できる」といった脆弱性の性質は、ベクトルを見ればすぐに分かります。

## 2.2 どのバージョンが使われているか

CVE List のレコード（CNA や ADP が付けたもの）に含まれる CVSS のバージョンを数えると、次のようになります。

| 公開年 | CVE 数 | v3.1 あり | v4.0 あり | CVSS なし |
|---|---:|---:|---:|---:|
| 2023 | 28,847 | 76% | 0% | 20% |
| 2024 | 39,924 | 87% | 9% | 6% |
| 2025 | 48,152 | 82% | 26% | 6% |
| 2026（10月20日まで） | 82,964 | 82% | 32% | 6% |

1 つの CVE に複数のバージョンのスコアが付くこともあるため、合計は 100% になりません。**現在の主流は v3.1** で、v4.0 は徐々に増えている段階です。

## 2.3 CVSS v3.1（2019年6月公開）

v3.1 は v3.0（2015年）の改訂版です。評価項目は次の 3 つのグループに分かれています。

| グループ | 誰が評価するか | 評価項目 |
|---|---|---|
| **基本評価基準（Base）** | ベンダー・CNA | 攻撃経路（AV）、攻撃条件の複雑さ（AC）、必要な特権レベル（PR）、ユーザー関与レベル（UI）、スコープ（S）、機密性・完全性・可用性への影響（C / I / A） |
| **現状評価基準（Temporal）** | ベンダー・CNA | 攻撃される可能性（E）、利用可能な対策のレベル（RL）、脆弱性情報の信頼性（RC） |
| **環境評価基準（Environmental）** | 利用者 | 機密性・完全性・可用性の要求度（CR / IR / AR）、各基本評価基準の修正値 |

特徴的なのが**スコープ（S）**です。脆弱性のあるコンポーネントの外（たとえば仮想マシンからホスト OS、Web アプリから閲覧者のブラウザ）にまで影響が及ぶ場合は「変更あり（C）」となり、原則スコアが上がります。

```
CVSS:3.1/AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:H/A:H   → 9.8（スコープ変更なし）
CVSS:3.1/AV:N/AC:L/PR:N/UI:N/S:C/C:H/I:H/A:H   → 10.0（スコープ変更あり）
```

**v3.0 からの主な変更点**

v3.1 は「新しい評価項目は追加せず、仕様を明確にする」ことを目的とした改訂です。

- **CVSS は「深刻度」を測るもので、「リスク」を測るものではない**と明記された。基本スコアだけで対応の優先度を決めず、環境評価や組織のリスク評価と組み合わせるべきだとされた
- 攻撃経路（AV）の説明から OSI 参照モデルの用語を外し、分かりやすい表現にした。「隣接（A）」には VPN などの限定されたネットワークも含むと明記された
- スコープの定義、ライブラリの脆弱性の評価方法（もっとも起こりうる最悪のケースで評価する）などの評価ガイダンスが追加・整理された
- 小数点の切り上げ（Roundup）関数を厳密に定義し、計算環境によってスコアがずれる問題を解消した
- 環境評価の計算式を修正し、修正した機密性への影響を大きくすると、かえってスコアが下がってしまう場合があった不具合を解消した
- CVSS に独自の評価項目を追加するための**拡張フレームワーク**が定義された

## 2.4 CVSS v4.0（2023年11月公開）

v4.0 は v3 系からの大きな改訂で、評価項目の見直しと計算方法の刷新が行われました。

| グループ | 評価項目 |
|---|---|
| **基本評価基準（Base）** | 攻撃経路（AV）、攻撃の複雑さ（AC）、**攻撃要件（AT）**、必要な特権（PR）、ユーザーの関与（UI）、**脆弱なシステム**への影響（VC / VI / VA）、**後続システム**への影響（SC / SI / SA） |
| **脅威評価基準（Threat）** | 攻撃の成熟度（E）のみ |
| **環境評価基準（Environmental）** | 要求度（CR / IR / AR）、各基本評価基準の修正値 |
| **補足評価基準（Supplemental）** | 安全性（S）、自動化可能性（AU）、回復性（R）、価値密度（V）、対応に必要な労力（RE）、提供者の緊急度（U） |

**v3.1 からの主な変更点**

- **スコープ（S）の廃止**：判断が難しく評価がぶれやすかったスコープを廃止し、代わりに「脆弱なシステム」（VC / VI / VA）と「後続システム」（SC / SI / SA）への影響を**それぞれ別に**評価するようになった
- **攻撃要件（AT）の追加**：競合状態に勝つ必要がある、特定の設定が必要など、攻撃が成立する前提条件を評価する。v3.1 では攻撃条件の複雑さ（AC）に混ざっていた要素を切り出したもの
- **ユーザーの関与（UI）の細分化**：「なし（N）」「受動的（P）」「能動的（A）」の 3 段階になった。「ページを見るだけ」と「ファイルを開いて操作する」を区別できる
- **現状評価基準を脅威評価基準に再編**：利用可能な対策のレベル（RL）と脆弱性情報の信頼性（RC）を廃止し、**攻撃の成熟度（E）だけ**になった。E の値は「攻撃あり（A）」「PoC あり（P）」「報告なし（U）」
- **補足評価基準の新設**：人命・安全への影響（S）や、攻撃を自動化できるか（AU）など、スコアには影響しないが対応の判断に役立つ情報を記述できる
- **安全性（Safety）の考慮**：環境評価基準で後続システムの完全性・可用性への影響に「安全（S）」を指定でき、IoT や医療機器、制御システムなどでの人命への影響を表現できる
- **名称の明確化**：どの評価基準を使ったスコアかを示すため、**CVSS-B**（基本のみ）、**CVSS-BT**（基本＋脅威）、**CVSS-BE**（基本＋環境）、**CVSS-BTE**（すべて）と呼び分ける
- **計算方法の刷新**：固定化された計算式ではなく、約 1,500 万通りのベクトルを 270 のグループ（MacroVector）に分け、専門家が順位付けした値を参照して補間する方式になった

同じ脆弱性でも、v3.1 と v4.0 ではスコアが変わることがあります。「ネットワーク越しに、認証なしで、ユーザーの操作なしに、システムを完全に乗っ取れる」脆弱性を例に比べてみましょう。

**攻撃の状況を指定しない場合**

```
v3.1: CVSS:3.1/AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:H/A:H                      → 9.8（Critical）
v4.0: CVSS:4.0/AV:N/AC:L/AT:N/PR:N/UI:N/VC:H/VI:H/VA:H/SC:N/SI:N/SA:N   → 9.3（Critical）
```

**「攻撃の報告なし」を指定した場合**

```
v3.1: CVSS:3.1/AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:H/A:H/E:U                  → 9.0（Critical）
v4.0: CVSS:4.0/AV:N/AC:L/AT:N/PR:N/UI:N/VC:H/VI:H/VA:H/SC:N/SI:N/SA:N/E:U → 8.1（High）
```

| 条件 | v3.1 | v4.0 |
|---|---|---|
| 攻撃の状況を指定しない | 9.8（Critical） | 9.3（Critical） |
| 攻撃の報告なし（E:U） | 9.0（Critical） | 8.1（High） |

計算方法が変わったため、この例では同じ性質の脆弱性でも v4.0 のほうがやや低いスコアになっています。また、v3.1 では「攻撃の報告なし」を指定してもスコアは 0.8 しか下がらず、Critical のままです。一方 v4.0 では 1.2 下がり、High に変わります。v4.0 では、脅威評価基準（E）を指定しないと「攻撃あり」として扱われ、**実際に攻撃されているかどうかがスコアにより強く反映される**ようになっています。

> **注意**：CVSS の基本スコアは「その脆弱性が最悪の場合どれだけ危険か」を示すもので、**あなたの環境でどれだけ危険か**を示すものではありません。また、同じ CVE でも CNA と NVD で異なるスコアが付くことがあります。2026年4月以降、NVD は CNA がスコアを付けている場合に独自のスコアを原則付けなくなったため、**誰が付けたスコアか**を確認することも大切です。

---

## この章のまとめ

- CVSS は脆弱性の**深刻度**を 0.0〜10.0 で表す指標で、スコアは**ベクトル文字列**から計算される
- 現在の主流は **v3.1** で、**v4.0** への移行が進みつつある
- v4.0 ではスコープの廃止、攻撃要件（AT）の追加、脅威評価基準の再編、補足評価基準の新設など、大きな見直しが行われた
- スコアだけでなく、**ベクトル**と**誰が付けたスコアか**を確認する

次の章では、CVSS 基本スコアの大小だけに頼らず、実際の悪用状況や資産の置かれ方をふまえて対応の優先度を決める「リスクベースのトリアージ」を見ていきます。
